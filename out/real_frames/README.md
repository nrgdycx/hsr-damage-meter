# 实机帧素材（P1 实机读数可靠性）

这里放**全分辨率的实机抓屏帧**，用来做"选哪一对 (框, bar_rows)"的离线回归
（`python tools/overlay/live_box_check.py`）。`samples/` 已在 `.gitignore` 里，
所以把**入库的那一份**放这里；原图（PNG）优先级更高，有的话脚本会优先用它。

| 文件 | 来源 | 分辨率 | 屏幕上的数字（真值） | 说明 |
|---|---|---|---|---|
| `live_2880x1800_73431_q88.jpg` | `samples/M_full_now.png`（2026-10-01 实机抓屏）| 2880×1800（DPI 200%）| **73431** | 原始 PNG 8.0MB → JPEG q=88（subsampling=0）1.6MB；**逐条复验过**：走同一条实时路径，JPEG 与 PNG 的读数完全一致（`73431`，置信 1.000）|

## 为什么用 JPEG 而不是 PNG

仓库不该塞 8MB 的 PNG；而缩放过的缩略图**不能**用来判定框
（`samples/M_dual_full_*.png` 就是 1500×937 的缩略图，读出来全是 `?`，只能作废）。
JPEG q=88 保留全分辨率，实测不影响这一帧的定位与读数（见上表）。

## 真值从哪来

* `73431` = 当时屏幕上显示的数字，用户核对过；记录在
  [`docs/剩余工作清单`](../../docs/剩余工作清单) 与
  `tools/overlay/verify_rootcause.py` 的脚本说明里。
* ⚠️ 这是**目前唯一一帧**有真值的全分辨率实机帧 → 结论强度有限；
  P1 的实机采集（`docs/实时链路与悬浮窗.md`）会往这里**继续加帧**，
  每加一帧都要在表里写清"来源 / 分辨率 / 屏幕上的数字"。

## 加新帧的规矩

1. 只加**全分辨率**帧（缩放过的没用，见上）；
2. 必须写清**屏幕上的数字**（人工核对，不许猜、不许带诱导）；
3. 大图压成 JPEG q=88（`subsampling=0`）再入库，并**复验**压缩前后读数一致；
4. 同步更新 `tools/overlay/live_box_check.py` 的 `CANDIDATES`/断言（如果需要多帧真值）。
