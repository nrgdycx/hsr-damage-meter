## 0. 先记住这个项目最重要的一条

> **本项目最危险的失败不是"崩溃"，而是"跑得起来但结论是错的"。**

已经真实发生过：
* 统筹会话早期那份读取器报"覆盖率 82.7%"，用真值一核对**全是假命中**

所以：**看到程序正常输出数字时，不要以为它是对的。** 必须验证。

## 2. 按层排查（症状 → 命令 → 改哪）

### 2.1 数字读错 / 读不出（A 线）

**先分清两种症状：**

| 症状 | 典型表现 | 先查什么 |
|---|---|---|
| **读不出**（空） | HUD 明明有数字，程序返回空 | 掩膜/颜色（数字颜色变了？）|
| **读错**（位数对但内容错） | `506286` 读成 `880066` | **字形提取**（笔画被掏空）—— 见下 |
| **少位** | `140280` 读成 `0130` | **裁剪框太窄**，最高位被切 |
| **多位（假字）** | `123692` 读成 `413?19400` | 链式连续性阈值太松，把杂散块当数字 |

**诊断命令**
```powershell
python tools/hud/diag_glyph.py       # 逐位打印：期望/读出/置信/**字形像素宽高**
python tools/hud/diag_mask.py        # 打印整个 HUD 掩膜字符画，直观看字形是否残缺
python tools/hud/diag_user_truth.py    # 位数对账 + 墨迹 vs 框界 + 框×链阈值扫描
python tools/hud/diag_font_scale.py    # 字号/字距实测
```

**⚠️ 本项目最重要的一条经验**（A 线血泪换来的）：
> **"读错内容"几乎总是字形提取问题，不是分类器问题。**
> 判据：**看字形像素宽度**。正常字宽 **29~33px**；如果出错的字形只有 **23px**（正常 30px），
> 那就是**被切缺了**，不是模型不认识。
> 根因通常是掩膜 `B >= 185` 只取了**淡黄辉光层**，把数字本身的**饱和黄笔画核心**（B≈150）排除了。

**改哪里**
| 症状 | 文件/参数 |
|---|---|
| 少位 | `hud_glyphs.py` 的裁剪框（往左放宽）|
| 读错/残缺 | `hud_glyphs.py` 的掩膜（辉光 ∪ 饱和核心 + 填洞 + 去背景金线）|
| 多位假字 | 链式连续性阈值（`read_hud.py` 的 20px）→ 改用**本串自校准**阈值 |
| 新字体/新字号 | 先看 `docs/HUD数字读取.md`（最小素材 = 一张截图）|

⚠️ **改掩膜/裁剪参数时，训练管线与推理管线必须同步**，否则"训练与推理不一致"。
各线已统一到 `hud_glyphs.py` 作为**唯一实现**（训练、离线、实时三方共用）—— 改它一处即可。

### 2.2 行动者认不出 / 认错（E 线）

| 症状 | 典型表现 | 先查什么 |
|---|---|---|
| **整帧弃权**（待复核） | 每帧都判不出来 | 是不是**新队伍**？模板库只覆盖见过的单位 |
| **偶然认错** | 偶尔把 A 认成 B | 分数与分差 → 是不是**过渡帧**（滑动/切换中）|
| **一直认错同两个** | 系统性地 A↔B | 两个单位**长得像**（如昔涟↔长夜月）|
| **分辨率一变全废** | 换了窗口大小就认不出 | 屏幕适配（线7）|

**诊断命令**
```powershell
python axis_actor.py --selftest          # 真值帧 + 缩放自检
python axis_actor.py 226 109 307         # 单帧：打印顶端 + 归属 + **分数 + 间距 + 标记 + 8 个候选分数**
python tools/axis/scale_check.py             # 卡面两种缩放的核对
python tools/axis/view.py                    # 出图看顶端卡长什么样
```

**判据（E 线的两道闸，非常有用）**
* 分数 **≥ 0.90** 且与第二名分差 **≥ 0.45** → 才给结论；否则「待复核」
* 单帧输出里会打印**全部 8 个单位的分数** → 如果第一名和第二名很接近，就是"像"或"过渡帧"

**读单帧输出时注意**
* `marker` 字段：`ally_dot` / `ally_star` / `enemy_dot` / `gold_aha` / `ally_diamond`
  * **圆点** = 按行动值排队的正常行动
  * **四角星** = **插入行动轴的行动**（立即行动/额外回合/欢愉技）
  * 这能直接告诉你"这是一次插入行动"
* `card_type`：`unit` / `enemy` / `aha` / `elation` / `empty`

**改哪里**
| 症状 | 做法 |
|---|---|
| 新队伍不认识 | 挖模板（照 E 线套路：固定顶端槽 + 灰度/梯度/色度三合一 NCC）|
| 过渡帧误判 | 调 `min_margin`（分差闸），或加多帧投票 |
| 分辨率/缩放 | `geometry.py`（线7 的动态定位）|

### 2.3 归属不对 / 事件切分不对（C 线 / 线4）

| 症状 | 典型表现 | 先查什么 |
|---|---|---|
| 事件数不对 | 一次攻击被拆成两条，或两次并成一条 | 切分阈值（空白间隔、重置判据）|
| 伤害值不对 | 段内取的"最大值"不是最终值 | 读数本身错（先回第 2.1 节）|
| 归属到错的人 | 明明是 A 打的算成 B | 行动轴读数错（先回第 2.2 节），或**锚点时间取错** |

**诊断命令**
```powershell
python -u events_v4.py --anchors    # 锚点对账（10一致/0不一致/8正确弃权）
python -u events_v4.py --summary    # 按角色汇总
python -u events_v4.py --compare    # 与旧表对照
python tools/events/diag_dense.py                   # 密帧诊断：同源核对 / 失败模式分类
python tools/events/account.py                      # 逐组算清 C 线54段 → 线4 42段 的账
```

**关键口径（已定案，别改错）**
* HUD「总伤害」= **一次攻击内累计** → 段内取**最大值**（同值取**最早**那帧）
* 切分四条判据（见 `docs/归属与事件切分.md` §3.1）：空白≥1.5s 断开 / 数值降20%断开 /
  归属者变化且数值没继续涨断开 / 召唤者→忆灵断开
* 归属锚点的行动者要在 **[-1.5s, +0.5s]** 窗口里找，且**优先取锚点之前**的

**改哪里**：`events_v4.py` 的 `segment()` / `attribute()`

### 2.4 报错 / 崩溃

| 报错 | 原因 | 修法 |
|---|---|---|
| `FileNotFoundError: frames/glyphcache/...` | 抽帧缓存被删 | 重跑 `collect_glyphs.frame(t)` 会自动抽 |
| `IndentationError` / 中文变乱码 | **用 PowerShell 管道改过源码** | 用编辑器改回；⚠️ 以后别用 `Set-Content`/`-replace` 改 .py |
| `找不到 out/xxx.npz` | 产物被删 | 按对应线的复现命令重建 |
| `cv2.error` 关于尺寸 | 帧分辨率不一致 | 屏幕适配（线7）|

**⚠️ PowerShell 改源码是本项目的已知杀手**：会毁 UTF-8 中文 + 吃行首缩进。
正确做法：用编辑器工具改；若必须用命令行，改完**必须校验**：
```powershell
python -c "open('文件名','encoding'='utf-8').read()"
```

## 3. 输入变了怎么办（不改代码，先判断）

| 变化 | 判断 | 对策 |
|---|---|---|
| **换了屏幕分辨率/窗口大小** | 跑 `geometry.py` 看定位是否还对 | 线7 的动态定位 |
| **换了队伍** | E 线全帧弃权 → 就是新队伍 | 挖模板（线2 的做法）|
| **遇到新玩法**（如阿哈时刻） | `card_type` 出现新值，或整段弃权 | 看 `docs/线3` 的思路 |
| **游戏更新改了 UI** | 掩膜/定位全失效 | 重新标定 HUD 框与行动轴位置 |
| **数字变得更大/更小** | 少位或多位 | 调裁剪框宽度 |

## 2. 上次整理遗留的、这次要注意的

### ⚠️ 坑1：`samples/` 被 ignore，但文档引用它（**上次已经踩过一次**）
* `samples/` 有 120 张图 / 51MB，在 `.gitignore` 里
* 但**12 个文档正文引用了其中 22 张当证据图**
* 上次的解法：把被引用的图复制到 `docs/images/`（入库），并改掉引用路径
* **这次整理后必须再查一遍**：
  ```powershell
  # 找出正文引用了但仓库里没有的图
  python -c "
  import glob,os,re
  refs=set()
  for p in glob.glob('docs/*.md')+glob.glob('*.md'):
      t=open(p,encoding='utf-8',errors='replace').read()
      for m in re.finditer(r'(?:docs/)?images/([A-Za-z0-9_\u4e00-\u9fff\.\-]+\.png)',t): refs.add(m.group(1))
      for m in re.finditer(r'samples/([A-Za-z0-9_\u4e00-\u9fff\.\-]+\.png)',t): refs.add('!!samples/'+m.group(1))
  have=set(os.listdir('docs/images'))
  bad=[r for r in refs if r.startswith('!!samples/') or r not in have]
  print('断链:', sorted(bad) or '无')
  "
  ```

### ⚠️ 坑2：各线用后缀区分脚本（`_A/_B/_C/_E/_L2/_L4/_L6/_L7/_M`）
* 好处：并行会话不冲突
* 坏处：根目录一堆脚本，**看不出哪条线是主线**
* **建议**：整理时按线建子目录（`lines/A/`、`lines/E/`…），
  但**先 `git mv` 再改 import**，别直接删

### ⚠️ 坑3：`out/` 里有大量过程产物
* 如 `L4_run1.log` ~ `L4_run16.log`（16 个迭代日志）、`frames_dense_C.csv`（**已被取代的旧密帧表**）
* **别删**，但可以：
  * 把 `L4_run*.log` 归到 `out/logs/`
  * 给**已被取代**的产物加 `_deprecated` 后缀或移到 `out/archive/`

### ⚠️ 坑4：文档里的结论会互相矛盾
* 本项目真实出现过：`用户口径与铁律.md` 说"HUD 停留 1~1.5 秒"，实测 **~0.5 秒**；
  说"端到端 4/5"，修好后是 **5/5**；
  `伤害模型_D线_未被采信` 说"整局累计"，实测是"**一次攻击内累计**"
* **建议**：整理时建一个 `docs/已作废结论.md`，把矛盾/过期结论集中列出并指向前者

## 3. 整理的安全顺序

```
1. git status 看清未提交的东西（别在 dirty 状态下大动）
2. 先提交一版（保住现状，方便回滚）
3. 建 docs/已作废结论.md，把过期结论集中
4. 补图：跑上面的"断链检查"脚本，把被引用的图补进 docs/images/
5. 归位脚本：git mv 到子目录（不要直接删）
6. 归档产物：out/archive/ 放已被取代的表
7. 更新 docs/文档索引.md 与根 文档索引.md 的索引
8. 再提交一次
```

## 4. 整理时别做的三件事

3. ❌ **不要在整理时改识别逻辑**（整理和改代码混在一起，出问题无法定位是谁的锅）
