## 2. ⚠️ 未解决（新会话优先看这两条）

### 2.1 闪退的**根因**（只做了兜底）

现象：进战前/菜单停久了，手里的 `axis_geom` 与当帧抓到的裁剪区**不是一对**。

**已知**：
* 报错来自 `axis_actor.py:209`（"顶**墙**卡"）或 `geometry.py:467`（"顶**端**卡"）
* 实时抓的轴区域约 **280 宽 × 1260 高**；几何 `top_art` 到 (232,175)
* `axis_region_for(shape)` 返回 `(region, local_geom, global_geom)`，
  `live_mvp` 用的是第 2 个（本地）—— **这点没错**
* `live_mvp.py:186` 是唯一的赋值点：`self.hud_geom, self.hud_bar, self.axis_geom = hg, bar, ag`

**没查的**：慢一点时是哪一步让几何和裁剪区错配的
（`relocate()` 的时序？`note_hud_result` 触发重定位时机？标定文件与当前分辨率？）

**怎么定位**：实机跑一次，看日志里
```
[诊断] ... ｜ 行动轴 判出行动者 X/Y ｜ ...
```
若 `X/Y` 很低（<10%）→ 一直在走错配路径。
另外 `read_actor` 现在会返回 `reject="geom_mismatch"` / `reject="axis_error"`，
`--dump-readings` 出的 CSV 里能看到计数。

### 2.2 像素字体（狼尊强普）的**分割**不准

档案切换已生效，但用**用户确认过真值**的三张像素帧实测：

| 帧 | 真值 | 读出 | 问题 |
|---|---|---|---|
| t=238 | `123692` | `123692` ✓（置信 1.00）| — |
| t=100 | `506286` | 只切出 **5** 字形（应 6）| ❌ |
| t=200 | `2052321` | **切不出字形** | ❌ |

**根因（已量化）**：不是分类器，是**分割**。
`hud_glyphs.cyan_mask` 找的是"青绿填充"，而像素数字其实是**白色实心**；
关键是**相邻两位被粘成一个宽块** —— 实测 `w44/h76`、`w45/h86`（单字应 h≈50）
→ 字形数少 1 → 读数值不对。`_split_wide_off()` 目前**有意"不拆"**（历史上拆错过）。

**要彻底修好**：
1. 调 `cyan_mask` 或加"白色实心"通道；
2. 实现可靠的宽块拆分（可按 `CYAN_ADVANCE=59` 的字距推断应拆几位）；
3. ⚠️ **必须重训 + 重新验收**：`out/digit_dataset_yinlang999.npz`（74 样本），
   基线**留一帧 70/74 = 94.6%**、集成 **14/15 整串** —— 改完不许低于它。

| `hud_glyphs.py` | **掩膜/分割的唯一实现**（改它要重训+回归）|

| `events.py` / `events_v4.py` | 事件切分与归属判据 |
| `hud_pack.spec` | 打包资源清单（**漏一个就少一块功能**）|

### 命令

```powershell
cd D:\project\hsr-damage-meter
$env:PYTHONIOENCODING='utf-8'

python preflight.py                     # ⭐ 实机/发布前自查（23 项）
python eval_holdout.py                  # 数字识别回归 → 期望 29/29 + 5/5

python -u events_v4.py --anchors        # 归属回归 → 10/0/8
python mvp/live_mvp.py --selftest       # 实时链路自检（不需要游戏）
python build_exe.py --mode onedir --name HSR伤害统计   # 打包

# 实机（建议进战前就跑）
#   双击 dist\HSR伤害统计\HSR伤害统计.exe → 点「开始统计」
#   日志：dist\HSR伤害统计\运行日志.txt（每 2 秒一行 [诊断]）
```

### 实机日志怎么读（**用户报问题时先要这个**）

```
[诊断] 框来源=ink:120 ｜ 可信读数 45/180=25.0% ｜ 行动轴 判出行动者 60/180=33.3% ｜ 事件 5（待复核 2）
         ↑ 定位坏没有        ↑ 读数环节坏没有        ↑ 归属环节坏没有            ↑ 结果
```
* `框来源` 全是 `model:` → **定位坏了**（HUD 框没跟上实机）
* `可信读数` <10% → **读数环节坏了**
* `行动轴 判出行动者` <10% → **归属环节坏了**（可能就是 §2.1）
* 三个都正常但事件很少 → **切分口径问题**
