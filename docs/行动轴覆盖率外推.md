## 2. 先把"没结论"的 154 帧分成四类

原来的 CSV 只有一个 `card_type` 字段，`empty` 把**两件完全不同的事**混在一起：

1. **行动轴整列被动画藏起来**（战斗演出占满屏幕）；
2. **行动轴还在**（左边一列卡片看得见），只是**顶端那张卡被白闪/特效盖住**，识别器判不出来。

两者的处理方式完全不同（前者只能外推，后者顶端槽本身是可以人工读的），所以先加一个**与识别器无关**的信号：

### 2.1 行动轴可见性检测器（`axis_coverage.queue_feat`）

* 取**队列区**（参考坐标 `(66,210)-(300,1250)`，即顶端卡以下那一整列）
* 特征 = 该区域 **竖边均值**（`|Sobel_x|` 的平均）：
  轴可见时这里是十几张带边框的卡片 → 竖边很强；轴被隐藏时这里是战斗画面（左侧多是天空/背景）→ 几乎平滑
* **阈值 20**，随机抽 30 帧人工核对 → **30/30 全对**，而且间隙很宽：

| 人工判读 | 实测 `edge_v` 范围 | 检测器 |
|---|---|---|
| 轴可见（20 帧） | **29.6 ~ 54.7** | 全部判可见 |
| 轴不可见（10 帧） | **1.0 ~ 5.4** | 全部判不可见 |

（复现：`python tools/coverage/axis_hold_eval.py --labels`，标注在 `out/L6_manual_labels.json`，抽样图 `docs/images/L6_vis_page1.png`）

## 3. "行动轴被隐藏"的规律

外推段一共 **31 段**（外推出我方行动者的段），完整表在 `out/L6_eval.txt`。要点：

0. **段的形状**：两侧锚点都是我方且**同一人** 13 段 ｜ 两侧都是我方可**段内换人** 9 段 ｜ 后侧没有我方锚点（敌/阿哈/尾巴）9 段。
   第 5 节会看到，正是这三类的准确率差别巨大。

1. **长度**：1~11 秒（`118-128` 最长 11s）；超过 8s 的一律标"待复核"（见第 4 节）。
2. **成因四类**（都能在录屏里直接看到）：
   * **我方角色/忆灵的技能与终结技演出**（最常见：t=243 昔涟大招、t=276 死龙、t=216 小伊卡羽翼天马）
   * **敌方行动 / boss 机制演出**（t=158/197/290/330 一带，画面里是红发有翼的 boss，还有"「费达尔」的算法更接近【演化形态】了!"提示）
   * **波次切换**：t≈204「**战斗开始 2/2**」——这一帧**根本没有行动者**（证据 `docs/images/L6_full_e.png` 第 1 格）
   * **长演出/过场**：t=118~131 连续 14 秒**既没有行动轴也没有 HUD 读数**
3. **能不能预测？** 单看前一帧预测不了（同一帧前一秒还可能是敌人回合）。
   但**结构上一定夹得住**：隐藏段两侧总能找到"已知状态帧"（我方/敌方/阿哈），
   所以正确做法是**用两侧锚点外推**，而不是拿时间平均/固定网格去猜。
4. **隐藏段里确实在结算攻击**：31 段里有 **19 段**其前后的 HUD「总伤害」数值发生了变化
   （例：`153-155` 段 `324751 → 866730`；`261-266` 段 `721193 → 409984`）。
   剩下 12 段是纯演出（例如 `118-128` 整段没有 HUD 读数）。

## 4. 外推规则（`axis_coverage.extrapolate`）

对每一帧：

1. 识别器给出单位 → `source=read`（确定值，`tier=read`）。
2. 左标记是敌方 → `source=enemy`；金框 → `aha`；青色菱形（欢愉技卡）→ `elation`。
3. **左标记是青色（`ally_dot`/`ally_star`）** → "顶端站的是我方"这件事本身是确定的（只是认不出是谁）：
   追**上一个我方已确认帧**，`source=hold`。⚠️ **不能因为前面出现过敌方卡就顺延成敌方**
   （实测 t=108/257/284 就是这样被救回来的，见第 5.2 节）。
4. 其余（`hidden`/`blank`/`occluded`）→ 追**上一次已知状态**：
   * 上一次是我方 → `source=hold`（外推行动者）
   * 上一次是敌方 → `source=enemy`（**敌方行动的动画同样会把整条轴藏起来**，
     所以"上一帧是敌人"时不能继续给我方答案 —— 这是本次最重要的一条修正）
   * 上一次是阿哈 → `source=aha`
5. 超过 **`MAX_ADOPT_AGE = 8s`** 的外推一律进"待复核"（尾巴 `333-339` 最长要追 20s）。

派生列：

| 列 | 含义 |
|---|---|
| `source` | `read` / `hold` / `enemy` / `aha` / `elation` / `none` |
| `tier` | **A**=前后锚点都是我方的**同一人**；**B**=两侧都是我方可**换了人**；**C**=至少一侧不是我方（敌方/阿哈/缺失） |
| `hold_age` | 距前锚点几秒（外推的"新鲜度"） |
| `alt_owner` | **取前后锚点里时间更近的那个**（另一种口径："此刻顶端是谁"） |
| `verdict` | 推荐口径：`确定` / `采纳(外推A)` / `低可信(外推C)` / `待复核(外推B换人)` / `待复核(外推>8s)` / `待复核(阿哈)` / `非我方` / `无` |

## 5.4 【定案】tier B 采不采 —— **不采**（《剩余工作清单》【线6】尾巴 1）

**结论：只采 tier A；tier B 一律标「待复核」，不进任何主表。**

| 档 | 帧数 | 回测 | 人工抽样 | 定案 |
|---|---|---|---|---|
| 确定（E 线直接识别） | 86 | — | — | **采** |
| **tier A**（前后锚点都是我方的**同一人**） | 37 | 97.1% | **10/10** | **采**（覆盖率 35.8% → **51.2%**） |
| tier C（至少一侧不是我方） | 22 | 91.7%（仅 12 样本） | **2/8** | **默认不采**，只在输出里标 `低可信` 供需要时取 |
| **tier B**（两侧都是我方可**段内换人**） | 30 | **46.4%** | **3/6** | **不采**（若某下游一定要用，必须带 `低可信` 标记） |

依据两次独立度量的**一致处**：只有 tier A 同时拿到"回测 97.1%"和"人工 10/10"；
tier B 两边都不过半；tier C 两次度量互相矛盾（回测 91.7% vs 人工 2/8，且回测只有 12 个样本），
按"宁可漏，不要错"降级为**不默认采纳**。

**已落进代码**：`axis_coverage.ADOPT_TIERS = ("A",)`；`verdict()` 对 tier B 返回 `待复核(外推B换人)`；
`is_adopted(r)` 只有 `确定`/`采纳(外推A)` 返回 True（`loose=True` 才加 tier C）。
要改口径：`python axis_coverage.py --stats --tier-policy A,B,C`。

## 6. 给 C 线的接法（建议）

用新文件 **`out/axis_actors_L6.csv`**（列是 E 线原来的 + `state/source/tier/verdict/unit_out/owner_out/alt_owner/hold_age/anchored` 等）：

```python
import csv
rows = {float(r["t"]): r for r in csv.DictReader(open("out/axis_actors_L6.csv", encoding="utf-8-sig"))}
r = rows[220.0]
# r["owner_out"]  -> "昔涟"        （外推/识别出来的归属）
# r["verdict"]    -> "确定" | "采纳(外推A)" | "低可信(外推C)" | "待复核(...)" | "非我方"
# r["hold_age"]   -> 0.0 / 追了几秒
# r["alt_owner"]  -> 取最近锚点的另一种答案
```

建议：

1. **默认采纳 `verdict ∈ {确定, 采纳(外推A)}`** —— 覆盖率 51.2%、准确率约 97%。
2. 需要更满的覆盖率时，把 `低可信(外推C)` 也纳入，但**在输出里保留 `hold_age` 和 `source=hold` 标记**，
   让用户能看出"这条是外推的"。
3. `待复核(外推B换人)`（30 帧）**不要当确定值用** —— 段内确实换了人，回测只有 46.4%。
4. `verdict=非我方`（56 帧）与 `待复核(阿哈)`（5 帧）不要算成我方伤害；
   阿哈那几帧的行动者是**框里头像**（线3 的活）。
5. ⚠️ **不要再相信"事件那一帧"**：隐藏段里事件帧经常整个是黑的，
   必须按 C 现有规则在窗口内取最近的**已确认或 tier A 外推**帧。

## 6.1 【定案】外推并进主表（《剩余工作清单》【线6】尾巴 2）

**做法**：`axis_coverage.join_events()` 把线6 的列挂到任意事件表上，**不改动原表**。

**对齐方式**：取事件自己的**归属帧** `actor_t`（没有就退到 `t_anchor`），
在 1 fps 网格上找**最近的那一帧**（`l6_dt` 给出偏移），把该帧的线6 结果写成 `l6_*` 列。

| 新列 | 含义 |
|---|---|
| `l6_t` / `l6_dt` | 对齐到的 1 fps 帧号 / 与事件归属帧的偏移（秒） |
| `l6_verdict` | 线6 的推荐口径（`确定` / `采纳(外推A)` / `低可信(外推C)` / `待复核(...)` / `非我方`） |
| `l6_source` / `l6_tier` / `l6_age` | `read`/`hold`/`enemy`/`aha`/`elation`；A/B/C；追了几秒 |
| `l6_owner` | 该帧的我方归属（敌/阿哈/无 → 空） |
| `l6_alt_owner` | 取最近锚点的另一种答案（对照用） |
| **`l6_adopted`** | **定案口径**是否采纳（`确定` 或 tier A）—— 下游直接看这一列 |
| `l6_adopted_loose` | 再算上 tier C（覆盖率更高、可信度更低） |
| `l6_agrees` | 基表 `owner` 与 `l6_owner` 是否一致 |
| **`l6_fills`** | 基表**没有**行动者、而线6 给出了 —— **这才是线6 给主表加的值** |

**产出（不动原表）**：

| 文件 | 结果 |
|---|---|
| `out/events_dense4_L6.csv` | 线4 主表（42 条）+ 线6 列：基表有行动者 34 条；**与线6 一致 40/42 = 95.2%**；**线6 补空 3 条**（e27@245.2→昔涟[tier A]、e31@264→遐蝶[tier B]、e42@339→遐蝶[tier C]） |
| `out/events_C_L6.csv` | C 表（54 条）+ 线6 列：**一致 54/54 = 100%**；**补空 6 条** |

**两处不一致（要说明，不是 bug）**：

* `e1`（`actor_t=102.6`）：基表用密集帧读到 102.6 的**死龙/遐蝶**；线6 的 1 fps 网格最近帧是 **103**（敌方卡）→ 报"非我方"。
  **这是 1 fps 与 0.2s 的分辨率差**，不是结论冲突。
* `e35`（`actor_t=284.2`）：基表 284.2 读**风堇**（=小伊卡卡面，人工核对过，对）；线6 在 284 帧外推成**长夜月**（tier B）。
  线6 已经在 §5.2 把这一帧列为人工核对的不一致例 —— 这次并表正好把它暴露出来，**以基表为准**。

**给线8/线5 的接法**：直接把 `out/events_dense4_L6.csv` 当主表底稿（是否取代 `events_C.csv` 由线8 定），
筛选 `l6_adopted == 1` 或者 `基表 owner 非空` 即可；`l6_fills == 1` 的三条是线6 唯一"新增"的事件归属。

```python

H.join_events("out/events_dense4.csv", out_path="out/events_dense4_L6.csv")   # 或命令行：
# python axis_coverage.py --join out/events_dense4.csv --out out/events_dense4_L6.csv
```

## 8. 已知坑 / 未做

1. ⚠️ **`card_type=empty` 不等于"轴被隐藏"**。必须用第 2.1 节的可见性信号区分；
   `occluded`/`blank` 帧的顶端卡其实**能人工读**（第 5.2 节的 L1 证据就是这么来的）。
2. ⚠️ **敌方行动的动画也隐藏整条轴**。"无脑 hold-last 我方"会给出过期答案
   （实测 t=288/322/323 顶端就是敌方卡）。本模块已改成"上一次已知状态是敌方就不给我方答案"。
3. ⚠️ **反过来也要防**：左标记是青色时，前面出现过敌方卡**也不能**顺延成敌方（t=108/257/284）。
4. **标记识别器是主要残余误差源**：它 89.8% 的准确率意味着大约每 10 帧就有 1 帧的阵营判错，
   而外推完全依赖它（`docs/images/L6_top_occ2.png` 里 t=288/322/323 都是漏检的敌方卡）。
   想再提精度，应该先修标记识别（尤其是**卡片滑动中的过渡帧**），不是改外推规则。
5. **阿哈时刻（录屏1 的 t=171~173 / 282~283）没有行动者**：需要线3 的框内头像识别，线6 明确弃权。
6. **波次切换帧没有行动者**：t≈204「战斗开始 2/2」；这类帧给任何行动者都是错的，
   目前靠 `hold_age`/`tier` 间接暴露，没有专门的"转场"检测器。
7. **只做了 1 fps 网格**。密帧（0.2s）上真正的风险是**静默少读几位（丢位碎片）**
   —— 见 [`归属与事件切分.md`](归属与事件切分.md) §1~2（"静默多读一位"那条旧结论已被线4 证伪）。
   线6 的外推/可见性判定同样只跑在 1 fps 上，密帧没做。
8. **并表只做了"挂列"**：`out/events_dense4_L6.csv` / `out/events_C_L6.csv` 是线6 的并表产物，
   **没有替线8 决定哪张是唯一主表**，也没有回灌线4 修正过的那 9 段数值 —— 那是【线8】的活。
9. **端到端没实测**（不需要用户配合的部分到此为止）；悬浮窗（线5）真正联调时，
   还要验证"实时 30fps 下用 `read_window` 投票 + 本线 `hold` 规则"的组合行为。
